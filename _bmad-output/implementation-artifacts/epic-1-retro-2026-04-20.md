## Succès

1. **Migration brownfield fluide** — Conversion legacy HTML+Excel → Express+SQLite sans régression. Chaque story livrait du fonctionnel.
2. **Pattern API standardisé** — `{ data: ... }` posé en Story 1.1, utilisé par toutes les stories suivantes sans modification.
3. **Pipeline middleware stable** — `static → json → cookie → helmet → auth → tableContext → routes → errorHandler` — posé une fois, jamais modifié.
4. **Couverture test exemplaire** — Croissance continue de 5 à 90 tests, zéro régression, zéro échec.
5. **Testabilité by design** — `createTestApp()` dans tests/setup.js, injection de dépendances dans le poller (fetchFn, getTableIdFn).
6. **Code reviews systématiques** — 5 patches réels attrapés et corrigés sur 3 reviews.
7. **Confiance Project Lead** — Process (tests + review) a permis une exécution autonome sans micro-management.

## Défis

1. **Story 1.1 surdimensionnée** — 22 sous-tâches (conversion ESM, schema 16 tables, migration, seed, Docker, Tailwind). Nécessaire comme fondation mais charge disproportionnée.
2. **Documentation Story 1.5 tronquée** — Completion Notes, Change Log et File List vides. Corrigé pendant la rétro.
3. **8 items différés accumulés** — 5 en Story 1.4, 3 en Story 1.5. Non bloquants mais dette à surveiller.
4. **Chemins de test manuels dans package.json** — Contrainte Windows (globs non supportés dans npm scripts). Risque silencieux si un test est oublié.
5. **Legacy CommonJS → ESM étalé** — Migration par story (1.1, 1.2, 1.4) plutôt qu'en une passe.

## Patterns identifiés

| Pattern | Fréquence | Impact |
|---|---|---|
| Chemins test ajoutés manuellement dans package.json | 6/6 stories | Risque d'oubli silencieux |
| Extension de tests/setup.js avec nouvelles routes | 4/6 stories | Positif — cohérent, mais fichier qui grossit |
| Réécriture legacy CommonJS → ESM | 3/6 stories | Migration réussie mais étalée |
| Items différés portés d'une story à l'autre | 2 stories | 8 items accumulés — dette |
| Patches code review sur bugs réels | 3/3 reviews | Positif — process fiable |

## Insights clés

1. La confiance Project Lead ↔ équipe technique repose sur le process (tests + review), pas sur le micro-management.
2. Les raccourcis documentaires se paient en traçabilité — un fichier story incomplet perd les leçons.
3. Les items différés s'accumulent si on ne les planifie pas activement dans les stories suivantes.
